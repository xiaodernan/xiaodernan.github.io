02 / WORK精选作品怎么读Reading the featured work

每张作品卡的结构一致，按这个顺序读，三十秒就能判断它值不值得点开：

Every card has the same structure. Read in this order and thirty seconds tell you whether it deserves a click:

  1. 标题与一句话定位：它是什么、解决谁的什么问题。
  2. Title and one-line positioning: what it is and whose problem it solves.
  3. 实测读数格：提交数、用例数、卷数、延迟等；带 latest.json 的卡片会自动刷新。
  4. Measured figures: commits, tests, volumes, latency; cards backed by latest.json refresh themselves.
  5. 技术标签：用到的语言、框架与基础设施。
  6. Tech tags: languages, frameworks, and infrastructure actually used.
  7. 链接行：源码、在线看板、路线图。看到「源码」就说明可以逐条核验。
  8. Link row: source, live dashboard, roadmap. A “source” link means you can verify every claim.

筛选按钮在作品区上方：按「Agent / 文档智能 / 游戏世界 / 数据平台」等类别过滤。再次点「全部」恢复。

Filter buttons sit above the work grid: filter by Agent, document intelligence, game world, data platform, and so on. Click “All” to restore.

06 / ADMIN管理员页与数据边界Admin page & data scope

页脚与说明书右上角都有「管理员」入口，口令固定为 123。它打开的是一个行为观察面板，用来查看访客在这台浏览器里留下了什么：

The footer and the top right of this booklet both link to “Admin”, passcode 123. It opens a behaviour panel showing what visitors left in this browser:

  • 会话与停留：访问次数、平均停留、快速退出比例（不足八秒即离开）。
  • Sessions and dwell: visits, average dwell, quick-exit share (leaving under eight seconds).
  • 点击热区与迷失点击：哪些区块被点得最多，哪些点击落在了不可交互的区域。
  • Click zones and lost clicks: which blocks draw clicks, and which clicks land on non-interactive areas.
  • 连续点击：一秒内同一位置连点三次以上会被记为焦躁点击。
  • Rage clicks: three or more clicks in the same spot within one second.
  • 滚动深度、语言与主题偏好：读完了还是只看了首屏。
  • Scroll depth, language, theme: did they finish the page or only see the hero.
  • 趋势与建议：按日聚合的走势，以及面板根据现有读数给出的下一步优化动作。
  • Trend and advice: daily aggregation plus next-step actions derived from the readings.
口径边界必须说清楚：Scope limits, stated plainly: 这是一个纯静态站点，没有服务端数据库。面板里的数据只来自当前这台浏览器的 localStorage，因此它是一份真实的本机观察记录，而不是全站全量统计。换一台设备、换一个浏览器，看到的是那一台自己的数据。面板上的每个数字都标注了采集口径，不做任何「假装有服务器」的推断。 This is a purely static site with no server database. Panel data comes only from this browser's localStorage — a genuine local observation record, not a site-wide census. Another device or browser shows its own data. Every figure states its collection rule; nothing pretends a server exists.

面板还提供「导出 JSON」与「清空本机记录」两个操作：前者用于把这份观察带走分析，后者用于重置为干净的初始状态。两者都只影响本机。

The panel also offers “Export JSON” and “Clear local records”: the first carries the observation away for analysis, the second resets to a clean state. Both affect this browser only.

07 / PROVENANCE数据口径Where numbers come from

  • 仓库数、星数、语言占比：GitHub REST API 实拉，按源码字节统计，不含 fork 与私有仓；面板底部写明抓取日期。
  • Repos, stars, language shares: pulled from the GitHub REST API, counted in source bytes, forks and private repos excluded; the fetch date is printed at the panel's foot.
  • 项目读数：来自各仓库公开的 latest.json 事实包，抓不到时回退到站点内置的同一份快照。
  • Project readings: from each repo's public latest.json fact pack, falling back to the same snapshot bundled with the site.
  • SpecProof 进度：同步自验收后端的真实运行记录，不是手填。
  • SpecProof progress: synced from the acceptance backend's real run records, not hand-filled.
  • 身份信息：姓名、学历、竞赛、实习、语言成绩均以本人提供为准，并由构建闸门逐字校验。
  • Identity: name, education, competitions, internship, and language scores follow the owner's own statement and are checked verbatim by a build gate.

08 / FAQ常见问题FAQ

页面上的数字会自己变吗？

Do the numbers update themselves?

会。带事实包的卡片在打开时拉取最新快照；拉取失败就保留内置快照，并在角落标注抓取日期，不会显示空白或占位符。

Yes. Cards with fact packs pull the latest snapshot on load; if that fails they keep the bundled snapshot and its fetch date. No blanks, no placeholders.

为什么有些入口标注「本地已验证」？

Why are some doors marked “locally verified”?

因为智能体运行时需要本机的模型与工具链才能跑，公网只提供界面与文档。标注状态是为了不把「能看」说成「能在线跑」。

Because the agent runtime needs a local model and toolchain; the public site only offers the UI and docs. The label keeps “viewable” from being sold as “runnable online”.

切换语言后为什么滚动位置还在？

Why does my scroll position survive a language switch?

切换是整块替换同一位置的节点，不重新加载页面，因此阅读位置、筛选状态与主题都保留。

The switch replaces nodes in place without a reload, so position, filters, and theme persist.

可以引用这里的数字吗？

May I cite these numbers?

可以，但请连同抓取日期一起引用；每个面板底部都有日期与统计口径，脱离口径的数字没有意义。

Yes, but cite the fetch date too; every panel prints its date and counting rule, and a number without its rule means nothing.

10 / TOUR十二步探索清单Twelve-step tour

如果不想读长文，就按这张清单走。每一步都能在两分钟内完成，走完等于把整站亲手验了一遍：

If long prose is not your thing, follow this list. Every step takes under two minutes; finishing it means you have tried the whole site by hand:

  6. Click ◐ to go dark, then back to light; reload and the choice persists.
  7. 打开 隐盾，粘贴一段含姓名与电话的文字，看敏感信息如何被标出与遮蔽。
  8. Open Yindun, paste text containing a name and a phone number, and watch sensitive spans get flagged and masked.
  9. 进 止音纪元九步教程，一步只学一个动作，走完再进世界。

  12. Search a place name in the world codex and confirm every hit carries its source.

  14. Read one Anthology short, then use the language button to compare its Chinese and English versions.
  15. 打开 Football OS，从档案架点开一卷真实决赛。
  16. Open Football OS and pull one real final off the archive shelf.
  17. 回到首页，用作品区上方的筛选按钮只看「游戏世界」，再点「全部」恢复。
  18. Back home, filter the work grid to one category, then click “All” to restore.
  19. 打开 管理员面板，输入 123；先看真实读数，再点「注入一组模拟样本」看趋势与建议如何变化。

  26. Shrink the window to phone width (about 390 px) and check that the hero, work cards, and filters never overlap or overflow sideways.
  27. 在首页按 Ctrl / ⌘ + F 搜「CÆSURA」，确认能定位到项目；再用仓库区的筛选按钮按类别过滤一次。
  28. Press Ctrl / ⌘ + F on the home page and search for CÆSURA, then filter the repo grid once by category.
